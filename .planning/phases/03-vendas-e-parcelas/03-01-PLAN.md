  <behavior>
    Módulo PURO (sem `server-only`, sem import de @prisma/client, sem `db`). Toda data é string "YYYY-MM-DD" ou componentes numéricos — NUNCA round-trip por `new Date(string)` ciente de timezone (usar apenas `Date.UTC` + getters `getUTC*` como em plano-comissao.service.ts). Dinheiro é `number` puro (o arredondamento fica na Fase 5; aqui só distribuímos valores conhecidos).

    FUNÇÃO 1 — `dataVencimentoAncorada(anoMes: string, diaAncora: number): string`
    - `anoMes` no formato "YYYY-MM" (ou "YYYY-MM-01"); `diaAncora` 1..31.
    - Retorna "YYYY-MM-DD" com o dia = min(diaAncora, últimoDiaDoMês). Clampa ao último dia do mês quando o dia âncora não existe naquele mês.
    - CRÍTICO (Pitfall 7): sempre computado a partir do `diaAncora` original, NUNCA a partir do resultado clampado do mês anterior.
    Cases:
      - dataVencimentoAncorada("2026-01", 31) -> "2026-01-31"
      - dataVencimentoAncorada("2026-02", 31) -> "2026-02-28"
      - dataVencimentoAncorada("2024-02", 31) -> "2024-02-29"  (bissexto)
      - dataVencimentoAncorada("2026-03", 31) -> "2026-03-31"  (voltou a 31, sem drift)
      - dataVencimentoAncorada("2026-04", 31) -> "2026-04-30"
      - dataVencimentoAncorada("2026-06", 15) -> "2026-06-15"

    FUNÇÃO 2 — `proximoMes(anoMes: string): string` (helper interno ou exportado): "2026-12" -> "2027-01". Somar meses SEMPRE via aritmética de calendário sobre componentes, nunca somando 30 dias.

    FUNÇÃO 3 — `gerarCronogramaParcelas(input): ParcelaGerada[]`
    Input (tipos exportados): { tipoPagamento: "a_vista" | "mensalista", mesReferenciaInicial: string /*"YYYY-MM" ou "YYYY-MM-01"*/, diaVencimento: number /*1..31*/, valorTotal: number, entrada: number, valorMensalidade: number, numeroParcelas: number }.
    ParcelaGerada (tipo exportado): { tipo: "ENTRADA" | "MENSALIDADE" | "AVISTA", numero: number, mesReferencia: string /*"YYYY-MM-01"*/, dataVencimento: string /*"YYYY-MM-DD"*/, valorPrevisto: number }.

    Regras (VENDA-02):
    - a_vista: retorna EXATAMENTE 1 parcela { tipo:"AVISTA", numero:0, mesReferencia = 1º dia do mesReferenciaInicial, dataVencimento = dataVencimentoAncorada(mesInicial, diaVencimento), valorPrevisto = valorTotal }.
    - mensalista:
        - Se entrada > 0: primeira parcela { tipo:"ENTRADA", numero:0, mesReferencia = mesInicial, dataVencimento ancorada nesse mês, valorPrevisto = entrada }.
        - Depois N parcelas MENSALIDADE (N = numeroParcelas), numero 1..N, uma por mês SUBSEQUENTE ao mês da entrada (se houver entrada) — ou começando no próprio mesInicial se entrada == 0. Cada mesReferencia avança via proximoMes; cada dataVencimento é ancorada NAQUELE mês a partir do diaVencimento original. valorPrevisto = valorMensalidade.
        - (Decisão de discretion, documentar no código: quando entrada>0 a ENTRADA ocupa o mesInicial e as mensalidades começam no mês seguinte; quando entrada==0 a 1ª mensalidade ocupa o mesInicial. Isso mantém "uma competência por mês, sem sobrepor entrada e mensalidade no mesmo mês".)
    - mesReferencia SEMPRE normalizado para "YYYY-MM-01".

    Casos de teste OBRIGATÓRIOS no parcelas.test.ts:
    1. Ano completo com âncora 31 a partir de "2026-01" mensalista, 12 mensalidades sem entrada: assert cada dataVencimento (jan-31, fev-28, mar-31, abr-30, mai-31, jun-30, jul-31, ago-31, set-30, out-31, nov-30, dez-31) — prova de não-drift.
    2. Fevereiro bissexto: âncora 31 em "2024-02" -> "2024-02-29".
    3. mensalista com entrada>0: primeira parcela é ENTRADA no mesInicial, mensalidades começam no mês seguinte, count = 1 + numeroParcelas.
    4. mensalista com entrada==0: primeira mensalidade no mesInicial, count = numeroParcelas.
    5. a_vista: exatamente 1 parcela AVISTA, valorPrevisto == valorTotal, no mesInicial.
    6. mesReferencia sempre termina em "-01".
