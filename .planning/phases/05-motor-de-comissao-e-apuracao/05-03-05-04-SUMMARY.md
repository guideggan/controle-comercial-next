# Phase 5 Plans 03+04: Apuração de comissão (snapshot) + UI de Comissões — Summary

Motor de comissão (05-01) ligado ao banco: `apuracao.service.ts` reúne plano
vigente + recebido no mês (papel-aware: closer via `porCloser`, SDR/SS via
`porSdr`), chama `calcularComissao` (motor puro, nunca cálculo inline) e grava
o snapshot `comissao_apurada` com `mesPagamento` explícito (mês de
referência + 1, via `mesSeguinte` pura e testada inclusive na virada de ano).
Mês `FECHADA` recusa reapuração; `fecharApuracao`/`reabrirApuracao` travam/
destravam o snapshot inteiro E `venda.fechado` na mesma transação,
substituindo o placeholder das Fases 3/4. `getExtrato` devolve o snapshot +
as parcelas pagas da competência (linha a linha, com aluno/tipo/valor) para
a UI. Todas as ações que afetam comissão (apurar, marcar/reverter pago,
trocar plano, fechar/reabrir) gravam `audit_log`.

A UI `/comissoes` (admin) lê o snapshot via `listarApuracoesDoMes` (nunca
recalcula), com seletor de mês, tabela por colaborador (papel, tipo de
plano, base, % aplicado, comissão, mês de pagamento, status) e botões
Apurar/Fechar/Reabrir (fechar com confirmação via AlertDialog). O extrato
`/comissoes/[colaboradorId]` mostra o resumo do snapshot + as parcelas
recebidas linha a linha + a fórmula aplicada (ex.: "R$ 3.000,00 × 3% =
R$ 90,00"). Item "Comissões" da sidebar deixou de ser placeholder.
