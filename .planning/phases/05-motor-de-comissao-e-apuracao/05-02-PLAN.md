<objective>
Criar o esquema durável da apuração: a tabela `comissao_apurada` (o snapshot
imutável por pessoa/mês que os painéis só leem) e a tabela `audit_log` (o
histórico de alterações que afetam comissão). Uma linha de comissao_apurada é a
saída persistida do motor — com mês de referência e mês de pagamento gravados
explicitamente (nunca derivados no read-time), inputSnapshot para auditoria/replay,
e status para o fecho/trava do mês.

Purpose: separar competência de pagamento (Pitfall 2), snapshot imutável
(Pitfall 4), trava de mês (Pitfall 5) e trilha de auditoria (Pitfall 4/AUDIT-01)
são decisões de schema que precisam existir ANTES da lógica de apuração (plano
05-03) — retrofit é caro depois de gravar dados.
Output: schema + migração aplicada; consumido pelo repo/service da apuração (05-03).
</objective>

  <name>Task 1: Enums e model ComissaoApurada (snapshot imutável, competência x pagamento, trava)</name>
  <files>prisma/schema.prisma</files>
  <action>
    Adicionar ao final de prisma/schema.prisma (seguindo EXATAMENTE as convenções do cabeçalho do
    arquivo: Decimal @db.Decimal(14,2) p/ dinheiro, Decimal @db.Decimal(6,4) p/ percentual,
    DateTime @db.Date p/ datas de competência, DateTime @db.Timestamptz p/ instantes, @@map em snake_case,
    id String @default(cuid())):

    enum StatusApuracao { ABERTA  FECHADA }

    model ComissaoApurada {
      id             String   @id @default(cuid())
      colaboradorId  String
      colaborador    Colaborador @relation("ComissaoColaborador", fields: [colaboradorId], references: [id])
      mesReferencia  DateTime @db.Date  // competência (1º dia do mês)
      mesPagamento   DateTime @db.Date  // mesReferencia + 1 mês, GRAVADO EXPLICITAMENTE (Pitfall 2/COMIS-04) — nunca derivado no read
      planoComissaoId String            // qual VERSÃO de plano foi usada (histórico intacto)
      plano          PlanoComissao @relation(fields: [planoComissaoId], references: [id])
      tipoPlano      PlanoTipo
      valorBase      Decimal  @db.Decimal(14, 2) // recebido no mês OU nº de calls (quando por_calls) — nunca TCV
      percentualAplicado Decimal? @db.Decimal(6, 4) // null quando por_calls
      valorComissao  Decimal  @db.Decimal(14, 2) // saída do motor, já arredondada uma vez
      inputSnapshot  Json     // ComissaoInput completo usado — auditoria/replay (COMIS-05, AUDIT-01)
      status         StatusApuracao @default(ABERTA)
      calculadoEm    DateTime @default(now()) @db.Timestamptz
      calculadoPor   String?  // userId (better-auth) de quem rodou a apuração
      fechadoEm      DateTime? @db.Timestamptz
      fechadoPor     String?  // userId de quem fechou o mês
      createdAt      DateTime @default(now()) @db.Timestamptz
      updatedAt      DateTime @updatedAt @db.Timestamptz

      @@unique([colaboradorId, mesReferencia]) // 1 linha por pessoa/mês; recomputa a ABERTA, nunca a FECHADA (regra no service 05-03)
      @@index([mesPagamento])                  // "o que é pagável neste mês" vira WHERE mesPagamento = X
      @@index([mesReferencia])
      @@map("comissao_apurada")
    }

    Adicionar a back-reference em Colaborador (model existente):
      comissoesApuradas ComissaoApurada[] @relation("ComissaoColaborador")
    E em PlanoComissao (model existente):
      comissoesApuradas ComissaoApurada[]

    Comentar no topo do model (como os outros models fazem) que a IMUTABILIDADE após FECHADA é
    imposta na camada de service (05-03), não só no banco — o índice único permite upsert da linha
    ABERTA; uma vez FECHADA o service recusa escrita.
  </action>
  <verify>rtk grep "model ComissaoApurada\|mesPagamento\|@@unique.*colaboradorId.*mesReferencia" prisma/schema.prisma</verify>

<task type="auto">
  <name>Task 2: Model AuditLog (trilha de alterações que afetam comissão) + migração</name>
  <files>prisma/schema.prisma</files>
  <action>
    Adicionar ao final de prisma/schema.prisma:

    enum AcaoAudit {
      MARCAR_PAGO
      REVERTER_PAGO
      EDITAR_VENDA
      TROCAR_PLANO
      FECHAR_APURACAO
      REABRIR_APURACAO
      APURAR_COMISSAO
    }

    model AuditLog {
      id          String   @id @default(cuid())
      acao        AcaoAudit
      entidade    String   // nome da entidade afetada: "parcela" | "venda" | "plano_comissao" | "comissao_apurada"
      entidadeId  String   // id do registro afetado
      colaboradorId String? // colaborador impactado (quando aplicável) — facilita filtrar o histórico por pessoa
      usuarioId   String?  // userId (better-auth) de quem executou; null p/ ações de sistema
      dadosAntes  Json?    // estado relevante antes (quando aplicável)
      dadosDepois Json?    // estado relevante depois
      criadoEm    DateTime @default(now()) @db.Timestamptz

      @@index([entidade, entidadeId])
      @@index([colaboradorId])
      @@index([criadoEm])
      @@map("audit_log")
    }

    Depois gerar a migração contra o Neon real:
      rtk npx prisma migrate dev --name add_comissao_apurada_audit_log
    (isto também roda prisma generate, atualizando o client com os novos tipos).
    Se o migrate falhar por drift/conexão, NÃO forçar reset destrutivo — reportar o erro no SUMMARY.
  </action>
  <verify>rtk npx prisma migrate status ; rtk grep "model AuditLog\|enum AcaoAudit" prisma/schema.prisma ; ls prisma/migrations | rtk grep add_comissao_apurada_audit_log</verify>
