## Decisions Made
- Nav items pass an icon **key** (not a `LucideIcon` component) across the Server→Client boundary; only the client-side `AppSidebarNav` resolves the key to an actual icon component, since functions/components cannot be serialized from a Server Component into a Client Component
- Kept `(admin)` layout's original inline `auth.api.getSession` check rather than switching to `requireRole("ADMIN")` — the DAL's `requireRole` throws on a role mismatch instead of redirecting, which would silently change UX for a non-admin visiting an admin route; deferred, since changing that behavior is outside a presentation-only phase's scope
- Removed the now-unused `logout-button.tsx` from `(colaborador)`, superseded by `UserMenu`'s dropdown in the sidebar footer

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Lucide icon components crossing the Server/Client boundary caused a 500 on every shell route**
- **Found during:** first smoke test of `/painel`, `/colaboradores`, `/produtos`, `/inicio`, `/vendas`, `/comissoes`, `/metas` with a real session cookie
- **Issue:** `nav-config.ts`'s `getNavSections(role)` (called from a Server Component layout) originally stored `icon: LucideIcon` (the component itself) in each nav item; passing that object into `AppSidebarNav` (a Client Component, needed for `usePathname`) threw `Error: Functions cannot be passed directly to Client Components`
- **Fix:** Changed `NavItem.icon` to a serializable string key (`NavIconKey`); moved the key→component lookup map into `app-sidebar-nav.tsx` (client-only)
- **Files modified:** `src/components/shell/nav-config.ts`, `src/components/shell/app-sidebar-nav.tsx`
- **Verification:** Re-ran curl smoke tests against all 7 routes with a real ADMIN session cookie — all returned 200 after the fix (previously 500)
- **Committed in:** `2f1dcab`
